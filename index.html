Как мы проверяем соответствие

Каждый Legal-компонент проходит этот чеклист перед добавлением в реестр

✓
Симметрия кнопок «Принять» и «Отклонить»

Обе кнопки имеют одинаковый визуальный вес, размер и расположение. Разный контраст — нарушение GDPR (Recital 32), основание для штрафа CNIL/ICO. Проверяется автоматически — click-parity тестом в CI.

✓
Скрипты аналитики не грузятся до согласия

GA, Яндекс.Метрика и др. подключаются динамически только после клика «Принять». Каждый компонент предоставляет onConsentGranted(callback).

✓
Согласие с версией и timestamp

localStorage хранит {version, timestamp, categories}. При обновлении политики конфиденциальности старое согласие инвалидируется автоматически.

✓
Возможность отозвать согласие

Ссылка «Настройки Cookie» остаётся доступной в любой момент через футер. Требование GDPR ст. 7(3) — согласие должно отзываться так же легко, как даётся.

✓
WAI-ARIA доступность

role="dialog", aria-modal, aria-label на кнопках, управление с клавиатуры. Требование EU Accessibility Act (июнь 2025). Проверяется axe-core в CI.

!
EU vs US — принципиально разные модели

GDPR: opt-in до установки нерекламных куки. CCPA: только возможность opt-out. Компоненты помечены тегами GDPR CCPA. Один баннер не закрывает оба требования.

Быстрый старт
Скопируй компонент, вставь в проект, адаптируй цвета. Никаких npm install.
Добавить компонент
PR с папкой component.html + meta.json. GitHub Actions проверит a11y и структуру.
Чеклист GDPR/CCPA
Полный список требований с примерами нарушений. Обновляется при изменении регуляторных гайдов.
Формат meta.json
Схема метаданных: title, tags, compliance[], author, version. Валидируется в CI.
Тестирование
axe-core для accessibility, Playwright для click-parity и e2e. Как запускать локально перед PR.
