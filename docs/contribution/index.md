# Как добавить компонент

Проект растёт за счёт контрибьюций. Чтобы процесс был предсказуемым и автоматизированным, каждый компонент — это папка с двумя файлами.

## Структура папки

```
components/
└── cookie-banner-sidebar/
    ├── meta.json        # метаданные для карточки и валидации
    └── template.html    # PREVIEW + CODE блоки
```

Имя папки = `id` компонента. Используй kebab-case, английский язык, без пробелов: `cookie-banner-sidebar`, не `Cookie Banner (Sidebar)`.

## meta.json {#meta-json}

```json
{
  "id": "cookie-banner-sidebar",
  "title": "Cookie Banner — Sidebar Variant",
  "category": "legal",
  "description": "Боковая панель вместо нижней полосы. Для сайтов с фиксированным футером.",
  "tags": ["GDPR", "A11Y"],
  "compliance": [
    "GDPR opt-in перед загрузкой скриптов",
    "Симметричный визуальный вес кнопок",
    "WAI-ARIA role=dialog"
  ],
  "regulatory_refs": [
    "GDPR Recital 32",
    "GDPR Art. 7 — conditions for consent"
  ],
  "author": "your_github_username",
  "version": "1.0.0",
  "copies": 0,
  "hearts": 0
}
```

### Поля

| Поле | Обязательное | Описание |
|---|---|---|
| `id` | да | Совпадает с именем папки |
| `title` | да | Название, показывается в карточке |
| `category` | да | Одно из: `legal`, `error`, `empty`, `anim` |
| `description` | да | 1-2 предложения, видно в карточке |
| `tags` | нет | Массив из: `GDPR`, `CCPA`, `A11Y` |
| `compliance` | для `legal` обязательно | Список того, чему соответствует компонент. Показывается в модале. |
| `regulatory_refs` | нет, но рекомендуется | Прямые ссылки на статьи законов. Это то, что отличает декларацию от доказательства — юрист компании должен суметь открыть первоисточник. |
| `author` | рекомендуется | Твой GitHub username |
| `version` | да | Semver, по умолчанию `1.0.0` |
| `copies`, `hearts` | нет | Начальные счётчики, обычно `0` |

Валидация: `category=legal` **требует** непустой `compliance[]` и хотя бы один тег `GDPR` или `CCPA`. Без этого CI зарубит PR.

## template.html

Файл состоит из двух блоков, разделённых маркерами:

```html
[PREVIEW]
<!DOCTYPE html>
<html lang="ru">
<head>
<meta charset="UTF-8">
<style>
  /* стили для живого превью внутри iframe карточки */
</style>
</head>
<body>
  <!-- интерактивная разметка: кнопки должны реально нажиматься -->
  <script>
    // вся логика — превью должно работать как настоящий компонент
  </script>
</body>
</html>
[/PREVIEW]

[CODE]
<!-- То, что увидит пользователь при копировании -->
<!-- Обычно похоже на PREVIEW, но без обвязки <html>/<head>/<body> -->
<div role="dialog" aria-modal="true">
  ...
</div>
<script>
  ...
</script>
[/CODE]
```

**Важно:** `[PREVIEW]` — это полноценный HTML-документ (с `<!DOCTYPE html>`), потому что рендерится в изолированный `<iframe sandbox>`. `[CODE]` — это фрагмент, готовый для вставки в чужой проект.

Превью должно быть **интерактивным**: если у компонента есть кнопки или тоглы — они должны реально работать в карточке, а не быть статичной картинкой. Пользователь должен увидеть поведение до того как скопирует код.

## Процесс

1. Форкни репозиторий
2. Создай папку `components/твой-компонент/`
3. Добавь `meta.json` и `template.html`
4. Локально прогони: `npm run validate`
5. Открой PR

GitHub Actions автоматически прогонит:
- **Структурную валидацию** — схема meta.json, обязательные поля
- **axe-core** — отсутствие критичных нарушений accessibility
- **Click-parity тест** (для legal-компонентов с Accept/Reject) — кнопки должны быть симметричны

Если все проверки зелёные — компонент уходит на ревью мейнтейнера.

## Не хочешь возиться с Git?

Используй [Issue-форму](https://github.com/casablanque-code/undercoverui/issues/new?template=new-component.yml) — вставь код, опиши компонент, мейнтейнер оформит PR за тебя. Автор будет указан как ты.
