# Чеклист Compliance & Тестирование

Этот документ объясняет, почему компоненты в реестре выглядят именно так — и как это проверяется автоматически, а не на словах.

## Почему это важно

Дизайн куки-баннера — не вопрос вкуса. Регуляторы прямо штрафуют за конкретные паттерны интерфейса. В декабре 2024 французский CNIL выписывал штрафы за высококонтрастную кнопку «Принять» против низкоконтрастной «Настройки». В марте 2025 Honda заплатила $632,500 за то, что opt-out требовал больше кликов, чем opt-in. Это не гипотетические риски — это прецеденты этого года.

## Чеклист для Legal-компонентов

### 1. Симметрия кнопок Accept/Reject

Обе кнопки должны иметь одинаковый визуальный вес: размер, цвет насыщенности, расположение. Если «Принять все» — крупная и зелёная, а «Отклонить» — серая ссылка мелким шрифтом, это классифицируется как dark pattern.

**Регуляторная база:** GDPR Recital 32 (consent must be freely given), гайдлайны CNIL и ICO 2022 года прямо указывают на «equal prominence».

**Как проверяем:** [click-parity тест](#testing) в CI — сравнивает bounding box обеих кнопок, фейлит при расхождении больше 15%.

### 2. Скрипты не грузятся до согласия

Аналитика (GA, Яндекс.Метрика) технически не должна выполняться, пока пользователь не нажал «Принять». Не «баннер показан», а именно «скрипт инициализирован».

**Паттерн в коде:**

```js
function cookieAccept() {
  saveConsent({ analytics: true })
  loadAnalytics() // скрипт грузится только тут, а не на загрузке страницы
}
```

**Регуляторная база:** GDPR Art. 7 — согласие должно предшествовать обработке данных, а не следовать за ней.

### 3. Версионирование согласия

`localStorage` хранит не просто факт согласия, а структуру с версией и временной меткой:

```json
{ "version": "1.0", "timestamp": 1719600000000, "categories": { "analytics": true } }
```

Когда политика конфиденциальности обновляется — версия меняется, старое согласие автоматически считается недействительным, баннер показывается снова.

### 4. Возможность отозвать согласие

Ссылка «Настройки Cookie» должна оставаться доступной — обычно в футере — постоянно, а не только при первом визите.

**Регуляторная база:** GDPR Art. 7(3) — отозвать согласие должно быть так же просто, как дать его.

### 5. WAI-ARIA доступность

Каждый legal-компонент с модальным поведением использует `role="dialog"`, `aria-modal="true"`, осмысленные `aria-label` на кнопках, и не ломает табуляцию клавиатурой.

**Регуляторная база:** European Accessibility Act, вступил в силу в июне 2025 — обязателен для сайтов, работающих с пользователями в ЕС.

### 6. GDPR ≠ CCPA

Это не один и тот же чеклист. GDPR требует **opt-in** до установки нерекламных куки. CCPA требует только возможности **opt-out** («Do Not Sell»). Компонент, закрывающий GDPR, не закрывает CCPA автоматически — отсюда раздельные теги в реестре.

## Тестовый стек {#testing}

### axe-core — accessibility

Каждое превью компонента прогоняется через [axe-core](https://github.com/dequelabs/axe-core) в headless Chromium через Playwright. Проверяется контрастность, наличие ARIA-атрибутов, структура заголовков.

```bash
npm run test:a11y
```

Компоненты с тегом `A11Y` проходят более строгий порог — ноль нарушений любой серьёзности, не только critical/serious.

### Click-parity тест — наш фирменный

Уникальный для проекта тест. Для каждого legal-компонента с парой кнопок Accept/Reject он:

1. Рендерит превью в headless browser
2. Находит обе кнопки по тексту
3. Сравнивает их `boundingBox()` — ширину и высоту
4. Фейлит сборку, если расхождение больше 15%
5. Проверяет, что обе кнопки — один и тот же HTML-тег (не `<button>` против `<a>`, что часто используется для визуального принижения)

```bash
npm run test:click-parity
```

Это автоматизированная версия того, что регулятор делает вручную при разборе жалобы — только запускается на каждый PR.

### Структурная валидация

Перед тестами в браузере — быстрая проверка `meta.json` по схеме: обязательные поля, допустимые категории/теги, semver-версия, обязательность `compliance[]` для legal-компонентов.

```bash
npm run validate
```

### Локальный прогон всего стека

```bash
npm test
```

Запускает валидацию → a11y → click-parity последовательно. Именно эта команда выполняется в CI на каждый PR.

## Что не входит в чеклист (пока)

Текущий стек не делает юридическую экспертизу — он проверяет паттерны интерфейса, не текст политики конфиденциальности. Раздел [«Verified by UndercoverUI»](/docs/changelog/) с подтверждением юристом — в роадмапе, но это отдельный, платный уровень проверки.
